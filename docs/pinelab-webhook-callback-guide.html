Pine Labs POS — Webhook Callback Integration Guide
Per-transaction notification setup for Pine Labs POS terminals

Integration Guidance
v1.0 · Sep 2026

1What this is

Pine Labs POS terminals push an HTTP POST to your server for each transaction. You host a single endpoint; Pine Labs calls it on every transaction. This enables real-time per-transaction notifications — no polling required.

Note: The authoritative field names and signature scheme come from your Pine Labs onboarding / integration contact. Naming differs slightly per integration type (PlutusSmart / Online Callback / Cloud API). The format below is what we receive in production and is a safe reference to build against.

2Setup (one-time)

  1. Stand up a public HTTPS endpoint, e.g. https://api.paymatrix.in/pinelab/notification.
  2. Share that URL with Pine Labs and ask them to enable transaction notifications / callbacks for your MID(s) / TID(s).
  3. Ask Pine Labs whether callbacks are signed and, if so, request the shared secret and the signature header name (we have seen x-pinelab-signature / x-signature).

3Endpoint requirements

MethodPOST
BodyJSON
ResponseReturn HTTP 200 quickly to acknowledge; process asynchronously

IdempotencyDeduplicate on TransactionNumber / PlutusTransactionReferenceID (retries can repeat the same txn)

4Signature verification IF SECRET PROVIDED

HMAC-SHA256 over the raw request body, hex-encoded, compared timing-safely:

const expected = crypto
  .createHmac('sha256', PINELAB_WEBHOOK_SECRET)
  .update(rawBody)          // exact bytes, before JSON.parse
  .digest('hex');

// compare against header x-pinelab-signature / x-signature (timing-safe)

6Parsing rules (important)

  • Amount is usually in paise → divide by 100 to get rupees.
  • Status mapping: HostResponse == "00" or APPROVED → success; 05/51/DECLINED → failed; VOID/REVERSAL → voided; REFUND → refunded.
  • Act on success only for settlement; expect PENDING / FAILED callbacks too.
  • Auto-reversals may arrive as a later VOID/REFUND (or even FAILED) for a txn you already saw approved — handle the reversal.
  • Store the entire raw payload for audit.

8Go-live checklist

  1. HTTPS endpoint returns 200 to Pine Labs' test call.
  2. Signature verification working (if secret provided).
  3. Amount-in-paise conversion verified against a terminal receipt.
  4. Idempotency + status mapping tested (success, fail, void / refund).
  5. Pine Labs enables callbacks for your live MID / TIDs.
